Agent Skill · self-contained

ClarifyTurn "make it nice" into one instruction both sides would agree to — using as few questions as the context allows.

A question is a cost. Someone who says make it nice is delegating; answering a ten-minute reversible change with three questions bills them for the agent's uncertainty. Clarify spends its effort on reading context, and its questions only on what reading cannot settle. Clear means agreeable, not merely measurable — the run ends when the person who asked can read the instruction and say yes, that is what I meant.

01 The gate — most requests do not need this

The first thing the skill does is try not to run.

Two sentences have to be writable without inventing anything: what the person is actually after, in their own words, and who looks at what, and decides it is done. If both write themselves, Clarify does not fire — the request is executed as given. Only one of them missing tells you which half the run is for: an intent with no condition needs grounding, a condition with no intent needs one question.

Both halves, or neither

A measurable criterion serving the wrong intent is precise and useless. A shared intent with no checkable condition is a mood two people happen to share. Agreement is the test; measurability is what makes agreeing to it safe.

Symmetry

Firing on an already-clear request is the same defect as executing a vague one. Both spend the requester's attention on the agent's uncertainty.

A shut gate still says so, in one line — clarify: gate shut — <the done-sentence>. That line is the entire output. A skill that declines silently leaves no evidence it declined, and no way to notice it has stopped earning its place.

Six classes of vagueness

ClassShapeExampleWhat is actually missing
Evaluativejudgement word, no condition"make it nice"the axis of judgement and its bar
Unboundedclear verb, no edge"clean up around here"scope, and what must not change
Delegatedexplicit hand-off"whatever you think"nothing — a default is the answer
Rejectionnegative, unnamed delta"not quite it"which property of the last artifact is wrong
Importeda word from elsewhere"modern", "properly"the referent — modern compared to what
Quantified-soundingnumber-shaped, unmeasured"make it faster"the metric, the baseline, the target

False positives keep the gate shut: the vague word qualifies an already-specified change ("make the header spacing nice" fixes target, property and direction — only the amount is open) · the repo already answers it in a lint rule, a token set, or a sibling implementation · the work is small and reversible enough that showing an artifact is cheaper than describing one · the person has decided and is asking for execution.

02 The five-phase workflow

GATE → GROUND → RESIDUE → ASK → LOCK. Grounding always precedes asking.

01 · gate
Does this need clarifying
Neither the intent sentence nor the done-sentence writes itself. Otherwise: stop, and execute.
02 · ground
Fill from context
Artifact → neighbour → declared convention → this conversation → memory. Each filled item names its source.
03 · residue
What genuinely remains
Only where different answers change the deliverable and no default is defensible.
04 · ask
Closed choices, within budget
Recommended option first, each option naming a different artifact.
05 · lock
One instruction both sides agree to
Intent in their words, target, done-state, acceptance check, exclusion, defaults taken.

Grounding: what each source can settle

#SourceSettlesCannot settle
1The artifact itselfwhich defects actually exist, and their sizepreference among defensible options
2The neighbourhouse style, naming, density, structureanything the neighbour is itself wrong about
3Declared conventionthe bar the repo already holds itself toa bar the repo has never set
4This conversationwhat was already ruled outanything not yet discussed
5Durable memorystanding preferences across sessionswhether the preference still holds

An item answerable at levels 1–3 is never a question. Asking it announces that the context was not read.

03 The question budget

The count comes from reversibility and blast radius — never from how vague the request felt.

Blast radius \ ReversibilityReversibleIrreversible / outward-facing
Small — one file, a few lines, a local look0 questions. Take the default, state the short lock (one line), let the artifact be the answer1 question — confirmation only
Large — structure, many files, expensive to redo1 question — direction onlyup to 3 questions, then the lock waits for approval
Rounds

Round 1 asks up to the budget. Round 2 asks at most one question, and only where an answer opened a genuinely new fork. There is no round 3 — a second vague answer is itself a decision: it means you choose. Take the default, name it in one line, proceed.

A budget of zero is a real answer, not a shortcut. And an open question is never a stop: everything it does not gate keeps moving while it is open.

04 Translating the evaluative word

Eight evaluative words, and the axis each one is actually pointing at. The table says which axis to look along — never what to conclude. Read the artifact first.

properly / solidthe verification that is missingmatch the repo's existing bar
fast / snappya number: p95, bundle size, cold startmeasure now, target stated relative to now

The rows are keyed on the axis, not on the vocabulary, so a request in another language lands on the same row — the skill's reference carries the mapping for the one language it is most often asked in, and the two traps that come with it: a dropped subject leaves the target itself as residue, and its strongest delegation ("yoshinani") is stronger than "whatever you think", not weaker.

Grounding is finished for an item when it reads as an observable state rather than an adjective: card padding matches the list view at 16px, not the spacing is tidy. If the sentence still needs an adjective to carry its meaning, the residue is real and the question is earned.

05 Asking well

Every question is a closed choice whose options differ in the artifact, not in the adjective.

The shape

Card spacing (recommended: A)
  A. Match the list view at 16px
     — consistent with what exists, nothing distinctive
  B. Widen to 24px and let the card lead
     — items per screen drops from 6 to 4

Recommended option first and viable on its own; two to four options; one line of consequence each — what the person gets, what they give up.

Bad shapes

BadWhy
"What would you like to do?"hands the work back
"What matters most to you?"asks for a value, not a decision
A/B/C/D/Ea menu is a deferral
"Should I write tests?"the repo already answered
Show instead of ask

Where the variable is taste and the second candidate is cheap to build, build both. A rendered pair asks the question better than any sentence, and it fails safe: if neither lands, the reply names the delta and grounding restarts with real evidence. Not for schema shape, migrations, or anything expensive to build twice.

06 The lock — the artifact this skill produces

Fewer questions, nothing hidden: every value taken without asking appears here with its source.

## Locked instruction
- Intent:         <one sentence, in the requester's own words>
- Target:         <file / screen / range — where the change stops>
- Done state:     <observable state after the change, no adjectives>
- Acceptance:     <who runs or looks at what, and what result settles it>
- Not doing:      <at least one — the tempting adjacent thing>
- Defaults taken: <item — value — source>
- Open:           <item, and why it does not block> | none

The field set is the contract; the labels are not. The block is rendered in whatever language the run is speaking — the same seven fields, in the same order.

Short form — the zero-question path

When the budget was zero and nothing is open, the full block costs more than the change it governs. The same fields collapse into one line, every slot still present:

lock: <intent> → <done state>; checked by <acceptance>;
      not touching <exclusion>; default <item = value, source>

Anything open, any question asked, or any irreversible work goes back to the full block. The one slot a squeezed format drops first is not touching — and that is the one holding the scope still.

  • Intent is the sentence the person would sign — their vocabulary, not the agent's. It is the field agreement actually happens on; every other field exists to make that agreement checkable. A guessed intent stated plainly can be corrected in one word.
  • Done state must survive the adjective test: delete every evaluative word and it still says what will be true.
  • Acceptance is a command, a comparison against a named reference, or a number against a baseline. "You'll see it" is not an acceptance condition.
  • Not doing is never empty — the exclusion is the cheapest scope control available.

How agreement is taken

WorkHow agreement is taken
Reversible, smallState the lock, proceed on non-objection — the artifact arrives before an objection would have
Reversible, largeState the lock, start on the part nobody could object to, hold the contested part one beat
Irreversible / outward-facingExplicit yes. Non-objection is not assent when undoing is expensive

A correction to the intent line is the cheapest possible outcome, not a failed run: re-ground from the corrected sentence, and leave the fields nobody disputed alone.

After the lock

The lock is a ceiling, not a floor. A further improvement found while working is offered in one line and left to the person — absorbing it silently converts "make it nice" into an unrequested rewrite, which is the original failure with better intentions.

07 Traps

Over-clarifying is the dominant failure, not under-clarifying.

  • Interrogating a delegation. "Whatever you think" is an answer. The response is the shortest correct artifact plus a line saying what was assumed.
  • Clarifying the whole sentence when one word is vague. The specific parts of a request are load-bearing; re-asking them reads as not having listened.
  • Dictionary translation without looking. "Modern" mapped to a fixed recipe produces exactly the generic default the word was complaining about.
  • Options that differ only in adjective. If the reader cannot picture two different artifacts, the question is unasked.
  • Budget inflation from discomfort. Vagueness felt is not blast radius.
  • Clarifying instead of working. A perfect instruction that arrives after the person could have had the artifact is a failure of the method, not a success.

08 Install

The skill directory is what gets linked; the README and the test battery stay behind.

make link                      # every agent CLI installed here
make link AGENT=codex          # just one — claude | codex | agy
make link PROJECT=/path/repo   # that repository, not the home directories
make status                    # where is it linked?
make unlink                    # remove only the links pointing at this repo
make check                     # references, counts and identifiers agree
make test                      # the fixture battery over check and link

Nothing at the destination is ever overwritten: a real directory, or a symlink into another checkout, is refused and left alone. A CLI whose own directory does not exist is skipped rather than created.

Invoke it as clarify, or /clarify in a slash-command harness — or let it trigger on its own whenever a request arrives with no achievement condition.
