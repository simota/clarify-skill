# questions — the shape of the ask

Purpose: how a question is written, how many, and what to do with the answers.
Read at `ASK`.

## Shape

Every question is a **closed choice**:

- the **recommended option first**, marked as such, and viable on its own
- 2–4 options, each naming **the difference in the artifact**
- one line of consequence per option — what the person gets, what they give up
- never an "or something else?" tail as a substitute for thinking of the third option

```
Card spacing (recommended: A)
  A. Match the list view at 16px — consistent with what exists, nothing distinctive
  B. Widen to 24px and let the card lead — items per screen drops from 6 to 4
```

## The one question worth more than the others

A question that tests **intent alignment** buys more than any question that fills a parameter,
because every parameter is downstream of it. Ask it as a statement to agree with, not as an
open question:

```
Taking the goal to be "pick one row from the list without hesitating" (recommended: A)
  A. Go with that — spacing and line height change, colour stays as it is
  B. Actually it is "fit more on screen" — the opposite: density up, spacing down
```

The person answers in one word, and a wrong guess costs one word to correct. **A guessed intent
stated plainly is safer than a correct intent left unstated** — the first can be disagreed with.

## Bad shapes

| Bad | Why | Fix |
|---|---|---|
| "What do you want to do?" | hands the work back | offer two artifacts |
| "What matters most to you?" | asks for a value, not a decision | ask for the decision the value would drive |
| "Is a modern feel okay?" | confirms an unshared word | show two candidates |
| "A, B, C, D or E?" | a menu is a deferral | pre-eliminate to the two that differ most |
| "Should I write tests?" | the repo already answered | read the neighbours, take the bar, say so |
| three questions about one axis | one question, badly cut | merge into one choice |

## Rounds

- **Round 1** — up to the budget (0–3). Below the budget is fine; over it never is.
- **Round 2** — only when an answer opened a genuinely new fork. Maximum one question.
- **No round 3.** A second vague answer is a decision: it means *you choose*. Take the
  default, name it in one line, proceed. Re-asking after a delegation is the fastest
  way to make the skill worse than not having it.

## Show instead of ask

Where the variable is taste and the second candidate is cheap to build, **build both**.
A rendered pair asks the question better than any sentence, and it fails safe: if
neither lands, the reply names the delta and grounding restarts with real evidence.

Applies to: visual design, copy tone, layout density, naming sets.
Does not apply to: schema shape, irreversible migrations, anything expensive to build twice.

## Ending on agreement

The round ends at the lock, not at the last answer. State the intent line back once, in the
person's own words, together with what will be true when it is done — that sentence is what
they are agreeing to, and everything measurable in the lock exists to make agreeing to it safe.
**Silence on a reversible change is assent; silence on an irreversible one is not.**

## While waiting

Do everything the open question does not gate, and say in one line what waits on it.
A question is not a stop — a question with nothing moving behind it is.
