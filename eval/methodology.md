# Evaluation methodology (pre-edit)

The fixed corpus is synthetic, not a representative workload sample. A case supplies a request AND explicit context; it is not judged by its request string alone.
The baseline annotations are manual contract witnesses: concrete rule-following failure paths that the current text permits or pressures, not transcripts emitted by a CLI.
When broad and specific rules conflict, the witness follows the specific shortcut/cap; this deliberately exposes risk and does not estimate how frequently a model would choose it.
After-edit reading uses the same priority convention. A surviving contradiction is still-ambiguous, not an invented deterministic success.
Initial GATE metrics exclude continuation scenarios and report routing stubs separately. Unknown owner contracts have no binary gold label.
A gate-shut status line is user-visible noise, not an unnecessary *clarification question*. A wrong grounded value can have the correct gate label; its default error is scored separately.
Questions count independent user decisions. Selection/factual clarification and explicit action approval are separate counts. Four fields in one sentence still cost four decisions.
Invented-default/menu counts are witnessed events, not every imaginable violation. Recommendations alone are NOT counted as executed defaults.
Each status applies to the case's specified assertions, not every rule the case does not exercise. `still-ambiguous` includes known uncorrected failures and genuinely uncertain contracts because the requested four-way taxonomy has no separate `unfixed` label.
The local trace grader tests structured observational fixtures, not skill prose, and cannot certify that an agent would emit the annotated trace or that a cited source is actually authoritative.
Real CLI selection, empirical FPR/FNR, completion latency, abandonment, real user corrections and redo rates remain unknown.
